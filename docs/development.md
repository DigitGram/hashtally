# Developing HashTally

## How it works

The installer copies `src/` to `~/.local/share/hashtally/`, links `~/.local/bin/hashtally`,
and registers a desktop entry, a *hash file* MIME type and the icons. The right-click
entries are small Nautilus scripts (and Nemo/Caja scripts, when installed) that `hashtally` writes itself, named in the current
language. `core.py` holds all logic (no UI code), including the call to `gpg`; the `ui_*.py` modules only show it.

## Project layout

```
src/hashtally.py     entry point and command line; picks the window for the chosen mode
src/cli.py           terminal mode: the same work as the windows, as text (no GTK)
src/core.py          all logic: hashing, hash-file parser, GPG check, settings, Nautilus scripts (no GTK)
src/ui_gtk.py        GTK 4 / libadwaita entry: opens the window for the chosen mode
src/ui_common.py     shared widgets (ring, hero), formatters and the base window
src/ui_verify.py     the verify window; ui_create.py, ui_compare.py, ui_settings.py the other three
src/ui_about.py      artwork of the About dialog (ui_about_art.py)
src/i18n.py          tiny gettext replacement that reads po/*.po directly
po/                  translations (hashtally.pot is the template)
data/                desktop entry, MIME type, icons
install.sh           per-user installer and uninstaller
tests/test_core.py   checks for core.py, i18n.py and the translations
tests/install_test.sh  installs into a throw-away home and removes it again
tests/scenarios.sh   sandbox with ready-made hash files to try every window by hand
```

## Tests

```sh
pip install pyflakes && pyflakes src tests
python3 tests/test_core.py    # parser, create/verify round trip, translations
tests/install_test.sh         # install and uninstall in a throw-away home
```

The same checks run on every push via GitHub Actions (`.github/workflows/test.yml`): once on Ubuntu 24.04 (GTK 4.14,
the oldest supported) and once in an Ubuntu 26.04 container (newer GTK and Python lay out and behave differently).

## Try it yourself

```sh
tests/scenarios.sh
```

builds a throw-away folder `/tmp/hashtally-test` (nothing outside it is touched) with matching, changed, missing and
odd hash files, a signed hash file with an unknown key and a big file to cancel on, and prints what to click.
The unreadable-file case only shows up when you are not root.

## Translating

Translations are plain gettext `.po` files in `po/`, read directly at runtime (no `msgfmt` step).
English source strings are the message ids; missing entries fall back to English.
Messages with a number use real plural forms (`_n`), so every language can follow its own rule from the
`Plural-Forms` header of its `.po` file.

German is maintained by the author. All other translations were generated by an AI assistant and have not been
reviewed by native speakers; corrections are welcome as pull requests.

```sh
cp po/hashtally.pot po/fr.po     # then translate the msgstr lines, e.g. with Poedit
python3 tests/test_core.py       # checks every .po against the strings used in the code
```

After changing strings in the code, refresh the template and merge it into the translations:

```sh
xgettext --from-code=UTF-8 --language=Python -k_ -kN_ -k_n:1,2 --add-comments=TRANSLATORS --add-location=file \
         -o po/hashtally.pot src/*.py
for po in po/*.po; do msgmerge -U --no-fuzzy-matching --backup=none "$po" po/hashtally.pot; done
```

A language shows up in the settings as soon as its `.po` file exists; add its native name to
`NATIVE_NAMES` in `src/i18n.py` if you want more than the language code to be listed.
